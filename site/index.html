§2Method

Measured, not guessed

Luminex runs its own OpenBench instance. A candidate change plays the current engine until a sequential probability ratio test can tell a gain from noise.

  1. 1

    Pull request

    Each change comes with the mechanism it relies on and how it was checked.

  2. 2

    Seven builds

    Continuous integration compiles every target on Linux, Windows and macOS.

  3. 3

    SPRT

    Games at 10+0.1 against the current engine, until the test accepts a gain between 0 and 5 Elo or rejects it.

  4. 4

    Merge

    A pass merges. Results inside the error margin are decided openly, numbers in the commit.

    §4Inside the engine

    Two evaluations, one search

    Luminex pairs a quantized neural network with a hand-crafted fallback, behind a search built from the techniques that define modern engines.

    01Neural evaluation
    A 768-wide HalfKAv2_hm network with 32 king buckets. Its int16 accumulators follow every move incrementally, and the int8 layers behind them run on AVX-512 VNNI or AVX2.
    02Selective search
    Principal variation search with aspiration windows, null-move pruning, singular extensions, ProbCut, razoring, futility and late-move pruning, and late-move reductions.
    03Move ordering that learns
    Killer and counter moves, continuation and capture history, static exchange evaluation, and correction history that tunes static scores from what the search finds.
    04Many threads
    Lazy SMP: each search thread keeps its own network accumulators and shares one transposition table with the others.
    05Always a fallback
    Without a network file, a hand-crafted evaluation plays instead: material, piece-square tables, mobility, passed pawns and king safety. The engine says so in an info line rather than switching quietly.
    06Speaks UCI
    Load it in Cute Chess, Arena, Banksia, En Croissant or any other UCI interface. MultiPV, pondering, win/draw/loss output and Polyglot opening books are built in.

    An efficiently updatable neural network

    A move changes only the pieces that moved, so the first layer is updated with a few vector additions instead of being recomputed. Select a layer to see what it does.

    1. Every piece on its square, seen from each side and indexed by one of 32 king buckets (HalfKAv2_hm). About 32 of the 24,576 inputs are active in a position.

    2. The feature transformer: one int16 accumulator per side. A move adds and subtracts a few weight rows; a king move into a new bucket rebuilds that side.

    3. Side to move first, then the opponent. Each value is clamped to [0, 1] and squared, the squared clipped ReLU that gives the small layers more to work with.

    4. int8 weights. On AVX-512 VNNI hardware one instruction multiplies and accumulates 64 byte pairs.

    5. int8 weights followed by another SCReLU.

    6. A score in centipawns from the side to move's point of view, which the search uses at every node it evaluates.

    How it is trained

    By distillation: positions from Leela Chess Zero self-play, each relabeled with the score of a deep Stockfish search. The loss weights quiet positions, the ones the search actually evaluates, above captures and leaves positions in check out.

    The released network, luminex_sfq_i8.nnue, was trained this way. The data for the next round is public.

    §5Chronicle

    From first commit to 3255

    Nine months and 1,676 commits, from a handcrafted engine to a neural one, and every step since November measured on OpenBench.

    1. Jan 2026

      First commit

      27 January: a handcrafted evaluation and an alpha-beta search.

    2. Apr 2026

      Version 5

      The evaluation is rewritten from scratch (v5.0, 9 April), then tuned release by release.

    3. Jul 2026

      The first network

      12 July: Luminex plays with an NNUE for the first time. SIMD work then takes the network from 81,000 to 982,000 nodes per second.

    4. Aug 2026

      The handcrafted peak ≈2500

      Tuned by distillation, the classical evaluation reaches about 2500 on the Stash ladder (v5.16).

    5. Sep 2026

      gen768 ≈2800

      A 768-wide network becomes the default and NNUE is switched on for everyone (v6.1).

    6. Oct 2026

      3000 crossed ≈3030

      v6.3 ships a network trained on Leela positions labeled by Stockfish, with the loss weighted toward quiet positions.

    7. Nov 2026

      OpenBench, then v6.4

      Every change now passes an SPRT on a pool of Xeon workers. v6.4 ships the first week of them: the network loads by itself, and every download is built for the CPUs its name promises.

    8. Nov 2026

      v6.5 ≈3255

      A day of search work, each change through an SPRT: history that learns from failed moves, a hash table that keeps its best move, leaner extensions. +145 Elo over v6.4, and Stash 32 beaten. v6.5.1 puts the network inside every download.

    9. Next

      A network from public data

      Training on the T91 positions, about 800 million of them, published on Hugging Face.

    Run it

    The network is inside the program, so there is nothing else to download or place. Add Luminex to your chess interface as a UCI engine, or talk to it directly:

    uci
setoption name Threads value 4
setoption name Hash value 256
isready
position startpos moves e2e4
go movetime 2000

    Or build it

    With a C++23 compiler (GCC 13, Clang 15 or MSVC 2022 and newer) and CMake 3.20 or newer:

    git clone https://github.com/changcheng967/Luminex.git
cd Luminex
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

    Questions

    Good to know

    Is Luminex free?

    Yes. It is free software under the GNU General Public License v3: you can use it, study it, change it and share it. Parts of its foundation derive from Stockfish.

    Do I need the network file?

    No. Since 6.5.1 every download carries the network inside it and loads it by itself. To play with a different network, point the NNUEFile option at its file; to play with the handcrafted evaluation, roughly 500 Elo weaker, set UseNNUE to false. Before 6.5.1 the network was a separate file that had to sit next to the program, and version 6.3.0 loads it only through NNUEFile.

    Which download should I pick?

    The modern builds need AVX2, which almost every x86 PC from 2013 on has. On older processors, use the compatibility builds, which need only POPCNT (x86 CPUs from about 2008 on). Macs with Apple silicon use the macOS build. This page marks the one for your system.

    Does it support Chess960 or endgame tablebases?

    Not yet. Luminex plays standard chess only, and it does not probe Syzygy tablebases. It accepts the SyzygyPath option so interfaces don't complain, then plays endgames with search and evaluation alone.

    Can it play weaker, for practice?

    Not yet. Skill Level, UCI_LimitStrength and UCI_Elo are accepted for compatibility but have no effect, so Luminex always plays at full strength.

    How strong is it, really?

    About 3255 Elo at blitz, measured against Stash releases with known ratings. That is an estimate from engine matches, not an entry on a rating list; see Strength for the numbers.

    How are changes tested?

    On OpenBench, against the current engine, until an SPRT can separate a gain from noise. Every result, including the failures, is public on bench.luminexchess.com.

    How can I help?

    Report bugs or send pull requests on GitHub. Changes that affect play go through an SPRT before they merge.
