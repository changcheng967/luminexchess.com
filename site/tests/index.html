Testing The method

Measured, not guessed

Luminex runs its own OpenBench instance. A candidate change plays the current engine until a sequential probability ratio test can tell a gain from noise.

1. From idea to merge

How a change gets in

  1. 1

    Pull request

    Each change comes with the mechanism it relies on and how it was checked.

  2. 2

    Seven builds

    Continuous integration compiles every target on Linux, Windows and macOS.

  3. 3

    SPRT

    Games at 10+0.1 against the current engine, until the test accepts a gain between 0 and 5 Elo or rejects it.

  4. 4

    Merge

    A pass merges. Results inside the error margin are decided openly, numbers in the commit.

Four changes were merged although their tests failed: #5 repaired correctness bugs at a measured cost, and #10, #11 and the retuned constants in #57 landed inside the error margin. The other changes that failed were closed or dropped. The SEE rewrite, at +127, runs off the chart. One SPRT is left off: test 59, a network trained on a filtered dump that had learned that material is worth almost nothing (6 wins and 79 losses when it was stopped). Test 64 is listed although it was a match of a fixed 3,006 games, not an SPRT.

Between the tests, four SPSA runs of 80,000 games each retuned search constants: 27 of them, then all 29, then all 29 again with gen768r_03, then 13 margins with gen768r_04q (tune 83). That last run moved no margin beyond noise: the SPRT of its values was stopped after 1,026 games (test 84) and main kept its margins. The other fixed-length matches are not listed: the Stash ladder (tests 35 to 39), v6.5.0 against v6.4.0 (test 40) and main against v6.5.1 at three time controls (tests 77 to 79) are on the home page. The count of games is OpenBench's own count of every game played, the tuning runs included.
